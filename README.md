# The EPL Oracle

A Premier League fixture dashboard using TypeSafe AI's Jev through Vercel AI Gateway. Deploys to Vercel as a static frontend plus serverless functions, with Neon Postgres persistence after a verified migration.

## Architecture

- **Persistence is selected explicitly.** `PERSISTENCE_BACKEND=blob` retains the original three JSON files until cutover. `PERSISTENCE_BACKEND=neon` uses fixtures, runs, input snapshots, prediction revisions, attempts and results in Postgres. Neon imports must pass validation before the application can use them. API requests read persisted data; they do not call Jev.
- **Two Vercel Cron Jobs do all the work, once a day each:**
  - `/api/cron/fixtures` fetches the official fixture list and club stats from the Fantasy Premier League API, rebuilds the upcoming-fixture list, and saves actual results for completed predicted fixtures, comparing Jev's call against the real score.
  - `/api/cron/predictions` asks Jev to predict every fixture in the next unplayed gameweek that doesn't already have a prediction for its current form/stats, pacing requests and retrying on rate limits.
- **Read-only API routes serve the frontend:** `/api/fixtures` merges the persisted fixture list with any matching prediction; `/api/results` returns Jev's resolved track record and a running accuracy total.
- There is no manual "predict this match" control — every prediction is generated by the daily cron run, never on demand.

## Run locally

```sh
npm install
vercel link      # first time only, links this directory to a Vercel project
vercel env pull .env.local
vercel dev        # do not wrap this in an npm script — `vercel dev` detects and refuses that recursion
```

`vercel dev` needs `AI_GATEWAY_API_KEY` and `BLOB_READ_WRITE_TOKEN` in `.env.local` (pulled from the linked project once a Blob store is attached — see Deploy below). Without a Blob store, `/api/fixtures` returns a 503 until you trigger the cron routes once by hand:

```sh
curl http://localhost:3000/api/cron/fixtures
curl http://localhost:3000/api/cron/predictions
```

Run `npm test` for fixture, prediction, accuracy and migration-source tests. Set `TEST_DATABASE_URL` to also run real PostgreSQL integration tests; these use a temporary schema and remove it afterward. See [migration and rollback](docs/neon-migration.md) for the database verification and cutover procedure.

## Deploy to Vercel

1. `vercel link` then `vercel` (or push to a Git repo connected to a Vercel project).
2. Add a **Blob** store to the project (Storage tab) — this sets `BLOB_READ_WRITE_TOKEN` automatically for all environments.
3. Set `AI_GATEWAY_API_KEY`. For Neon, also set the pooled `DATABASE_URL` and complete [migration validation](docs/neon-migration.md) before setting `PERSISTENCE_BACKEND=neon`. Keep the Blob token for migration and rollback.
4. Optionally set `CRON_SECRET` — Vercel then sends it back as a Bearer token on every Cron Jobs request, and `/api/cron/*` verifies it before doing anything.
5. Deploy. `vercel.json` registers the two cron schedules (05:30 and 06:00 UTC) and the longer `maxDuration` the predictions job needs. Before data is loaded, the fixtures endpoint reports "not loaded yet". Neon requires an initialized schema and verified import before serving data.

## Behaviour

- Shows all unstarted future fixtures, including undated ones, with pagination, team search and gameweek filtering.
- Predictions cover the entire next gameweek (typically 10 fixtures), refreshed once a day. A prediction is invalidated and regenerated automatically if the underlying stats change (new results, rescheduled kickoff) before the fixture is played. Neon preserves earlier revisions and input snapshots, and saves each successful forecast with its attempt status in one transaction.
- Sends Jev current-season league records, goals and the five most recent completed matches for each team. No fabricated fixtures, predictions or fallback model.
- Calls `POST https://ai-gateway.vercel.sh/v1/evaluate` with model `typesafe-ai/jev`. One choice question evaluates home/draw/away and one selects a score from 0–6 goals per team. Score and outcome are independent model decisions and can disagree.
- Once a fixture finishes, its prediction is compared against the real result and added to the **track record**: outcome-correct and exact-score-correct are tracked separately, alongside a running accuracy total across the whole season.
- Provider failures are displayed with a retry control on the fixtures list. No stale or synthetic data is substituted if a feed is unavailable.

## Credentials

`AI_GATEWAY_API_KEY`, `BLOB_READ_WRITE_TOKEN` and `DATABASE_URL` are server-only Vercel environment variables, never sent to the browser. The app has no authentication of its own — before making this a public product, add one, plus per-user rate limits.
